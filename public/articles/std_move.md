## std::move

Прежде чем приступить к разбору `std::move` стоит разобраться с тем, что такое `rvalue` и `lvalue`

`lvalue` - left value, имеет место в памяти 
- есть адрес (`&x` работает)
- можно присвоить (`x = 5`)
- живет дольше выражения (именованная переменная)
```c++
int x = 5;    // x - lvalue (есть адресс, можно &x, можно x = 10)
x = 10;
int* p = &x;
```

`rvalue` - read value, временное значение
- нет постоянного адреса (нельзя `&(5)` - ошибка)
- нельзя присвоить (`5 = 10` ошибка)
- временное - живет до конца выражения (потом уничтожается)
```c++
5                      // rvalue (литерал)
x + 1                  // rvalue (результат выражения)
foo()                  // rvalue, если foo возвращает по значению (временный объект) 
vector<int>{1, 2} // rvalue (временный объект)
```

#### Зачем это различие - выбор конструктора

У класса может быть два конструктора - копирования/перемещения

```c++
class Vector {
    Vector(const Vector& other); // копирующий - принимает const lvalue&
    Vector(Vector&& other);      // перемещающий - принимает rvalue&&
};
```

Компилятор выбирает по категории аргумента:
- аргумент `lvalue` - копирующий (`const&`) - копия (дорого)
- аргумент `rvalue` - перемещающий (`&&`) - move (дешево)

```c++
vector<int> a{1,2,3};              // a - lvalue (именованная)
vector<int> b = a;                 // a - lvalue (копия, дорого)
vector<int> c = vector<int>{1,2,3} // временный - rvalue (ПЕРЕМЕЩАЮЩИЙ, дешево)
```

Есть lvalue `a`, нужно вызвать перемещающий конструктор, а не копирующий, но `a` lvalue и компилятор выберет копию

### `std::move` = приведение lvalue к rvalue
```c++
vector<int> a{1,2,3};         // a - lvalue   
vector<int> b = std::move(a); // std::move(a) - rvalue - ПЕРЕМЕЩАЮЩИЙ (move)    
``` 

`std::move(a)` - это `static_cast<vector<int>&&>(a)`. Приведение типа из `vector<int>` (lvalue) в `vector<int>&&` (rvalue-ссылка). Больше ничего. Не перемещает, не зануляет - только меняет категорию выражения с lvalue на rvalue

*Приведение к rvalue = сделать вид, что это временный объект, чтобы компилятор выбрал перемещающий конструктор/присваивание вместо копирования*

### Схема: что происходит с адресами при копировании vs перемещении
```c++
vector<int> a{1, 2, 3};
```
```
СТЕК                                    КУЧА (heap)
┌─────────────────────┐
│ a                   │
│  data_   = 0x1000 ──┼──────────────────►  ┌────┬────┬────┐
│  size_   = 3        │                     │ 1  │ 2  │ 3  │
│  capacity_ = 3      │                     └────┴────┴────┘
└─────────────────────┘                     0x1000  0x1004  0x1008
   адрес a: 0x7FF0
```

### Случай 1: копирование `vector<int> b = a;`
```c++
vector<int> b = a;   // a — lvalue → const& → копия
```
```
СТЕК                                    КУЧА
┌─────────────────────┐
│ a                   │
│  data_   = 0x1000 ──┼──────────┐
│  size_   = 3        │          │
│  capacity_ = 3      │          │
└─────────────────────┘          │
                                 ▼
                            ┌────┬────┬────┐   ◄── СТАРЫЙ буфер (остаётся у a)
                            │ 1  │ 2  │ 3  │
                            └────┴────┴────┘
                             0x1000

┌─────────────────────┐
│ b                   │
│  data_   = 0x2000 ──┼──────────┐
│  size_   = 3        │          │
│  capacity_ = 3      │          │
└─────────────────────┘          │
                                 ▼
                            ┌────┬────┬────┐   ◄── НОВЫЙ буфер (скопировали элементы)
                            │ 1  │ 2  │ 3  │
                            └────┴────┴────┘
                             0x2000
```

Как видно из схемы:
- `b.data_` указывает на новый буфер `0x2000`
- элементы `1, 2, 3` скопированы побайтово
- `a` полностью сохранил свой буфер `0x1000` оба объекта живут независимо

*Стоимость:* аллокация `0x2000` + копирование всех элементов

### Случай 2: перемещение `vector<int> c = std::move(a);`
```c++
vector<int> c = std::move(a);   // std::move(a) — xvalue → && → move
```
До:
```
СТЕК                                    КУЧА
┌─────────────────────┐
│ a                   │
│  data_   = 0x1000 ──┼──────────────────►  ┌────┬────┬────┐
│  size_   = 3        │                     │ 1  │ 2  │ 3  │
│  capacity_ = 3      │                     └────┴────┴────┘
└─────────────────────┘                     0x1000
```
После (move-конструктор «ограбил» a):
```
СТЕК                                    КУЧА
┌─────────────────────┐
│ a  (валиден, но     │
│     пуст)           │
│  data_   = nullptr  │   ◄── занулили (или оставили валидное пустое)
│  size_   = 0        │
│  capacity_ = 0      │
└─────────────────────┘

┌─────────────────────┐
│ c                   │
│  data_   = 0x1000 ──┼──────────────────►  ┌────┬────┬────┐   ◄── ТОТ ЖЕ буфер!
│  size_   = 3        │                     │ 1  │ 2  │ 3  │
│  capacity_ = 3      │                     └────┴────┴────┘
└─────────────────────┘                     0x1000
```
Что произошло:
- `c.data_` = тот же адрес `0x1000`, что был у `a`
- `a.data_` = `nullptr` (или пустое валидное состояние)
- буфер в куче не пересоздавался, элементы не копировались
- `a.size_ = 0`, `a.capacity_ = 0`

*Стоимость:* несколько присваиваний указателя/чисел. O(1), без аллокаций и без копирования элементов

Суть move: приёмник ссылается на те же данные, что и источник, а источник обнуляется
